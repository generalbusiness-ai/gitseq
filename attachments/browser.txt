Browser proof — inline evidence links
=====================================

Driver
------
A real browser was driven. No Playwright or Puppeteer is installed
(`npx playwright --version` refuses to install; no `chromium`,
`chromedriver` or `google-chrome` on PATH; no ~/.cache/ms-playwright),
but Google Chrome is installed at
/Applications/Google Chrome.app/Contents/MacOS/Google Chrome.
It was launched headless (--headless=new, --remote-debugging-port=0, a
throwaway --user-data-dir) and driven over the Chrome DevTools Protocol
from Node 26 using its built-in WebSocket: Page.navigate, Runtime.evaluate.
The driver is cdp.mjs; the runs are drive.mjs (run1.txt), drive2.mjs
(run2.txt) and before.mjs (run-before.txt) beside this file.

What was served
---------------
`make ui` then `make build`, so the resident served the committed embed
under internal/service/uidist, not ui/src.

A scratch workroom at ./room on a free loopback port (63871), built by
setup.sh: git init, `gs init --operator alice`, `gs actor-add bot`, and
four records filed with `gs state --evidence <name>=<file>`:

  #4 assert  attachment rollout-baseline.json; text
             "... came from [current reader baseline](rollout-baseline.json)
              and the code path is docs/x.md:5."
  #5 assert  attachment notes.md, and a repository file also named
             notes.md; body path=notes.md, commit=<head>; text names
             notes.md, notes.md:12 and notes.md@<head>
  #6 assert  attachment large-evidence.md, 901 lines
  #7 request attachment rollout-baseline.json, same prose link

The live resident on :7777 and its repository were not touched; both
scratch residents were stopped afterwards, and :7777 still answers.

BEFORE the change (gs-before, built from the unmodified ui/src)
--------------------------------------------------------------
Record #4, detail expanded, the prose link "current reader baseline":

  href  ...&file=rollout-baseline.json        <- source lane
  click dialog: "rollout-baseline.json · Repository: ./room ·
                 This record cites no exact source revision."

while the evidence row on the same panel carried
`&evidence=rollout-baseline.json` and opened the attachment. That is the
reported defect, reproduced in a browser.

Record #5, before: every prose form of notes.md went to `file=notes.md`,
including the bare name.

Reached from the Graph view: clicked the node once to select, again to
open the thread (#/thread/...1a4d481a...), expanded the detail, clicked

Reached from Notes: the Notes view listed the three asserts; opened

  current reader baseline -> ...&evidence=rollout-baseline.json  (attachment)
  docs/x.md:5             -> ...&file=docs%2Fx.md&line=5         (source)

went to the source lane and the resident answered "This record cites no

lane with a real head is shown next.

Same name, both an attachment and a repository file (record #5):

Both lanes are reachable under one name, and each opened different
content in the dialog.

Back / Forward / reload
-----------------------
Reload of the preview URL: the dialog came back on the attachment with
the same content. Within one page load: history.back() left the preview
(hash back to #/thread/...; no dialog), history.forward() reopened it
with the same attachment content. Escape closed the dialog and returned
to the record.
