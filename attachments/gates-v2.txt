   `go test ./...` reported rc=1 for one package, cmd/gs, at 601 seconds, with
   two failing tests: TestFilingDisclosesItsBasesBeforeSigning and
   TestBatchProcessReadsItsFileAndReportsFailures. The six-package gate above,
   which includes ./cmd/gs/..., passed at the same head, and so did ./cmd/gs/
   alone.

   Both failures have the same cause, and it is not this change.
   cmd/gs/main.go:2475 wraps the snapshot load in loadSnapshotWithProgress,
   which after one second writes "gs: verifying the durable log; this may take
   a while" to os.Stderr. TestFilingDisclosesItsBasesBeforeSigning captures the
   subprocess's stderr and asserts it is empty in two subtests;
   TestBatchProcessReadsItsFileAndReportsFailures merges stderr into stdout
   with exec.CombinedOutput and parses the result as JSON. When the machine is
   loaded enough for a snapshot to pass one second, both break. cmd/gs/main.go
   is byte for byte identical to the base commit in this head
   (`git diff d1ae6ade -- cmd/gs/main.go` is empty), and nothing in this change
   touches the snapshot path.

   Reproduced directly. Running
   `go test -count=1 -run TestFilingDisclosesItsBasesBeforeSigning ./cmd/gs/`
   repeatedly while a whole-module run occupied the machine produced
   "--- FAIL: TestFilingDisclosesItsBasesBeforeSigning/the_genesis_basis_is_quiet"
   once in three attempts, at 33.03 seconds, against 20.2 and 20.9 seconds for
   the two passes; six further runs after the load dropped all passed, as did
   an unloaded run at 9.8 seconds. That subtest's only assertions are that the
   command succeeded and that its stderr is empty.
